Диагностика выбирала направление отдельно для каждого маршрута по будущим восьми целям. С долей сдвинутого прогноза 20% она снизила WAPE на обеих датах и прошла заранее заданный порог 0.001 в пуле. Причинное правило выбрало сдвиг для 578, 597 и 632 маршрутов из 1 000. На фолдах 3, 4 и 5 абсолютная ошибка выросла на 654 222, 863 520 и 488 509 соответственно. В Q4 на фолде 5 она снизилась на 92 562 (0.038%). Условие по крупным маршрутам также выполнено на всех субботах.

Симметричное сглаживание использовало те же активные маршруты и тот же вес. Оно дало меньшую ошибку, чем выбор направления, на каждой из девяти дат. Субботняя сезонная база выиграла от обоих вариантов сглаживания, тогда как историческая прокси основного ансамбля проиграла от обоих. Исторического OOF полной 021a нет. Фолд 5 изучался ранее. Платформенная метрика 021a (Public Score 0.3248477 по уточнению пользователя) известна со слов пользователя и в расчётах не участвовала.

## Воспроизведение

Из корня репозитория выполнить:

```powershell
.\exp_021\.venv\Scripts\python.exe -B exp_023/peak_shift.py
```

Скрипт читает Train один раз, использует сохранённые маршрутные прогнозы и фиксированное сетевое правило 021a. Контрольные значения — pooled Score 008b 0.3302594869 и WAPE сети 021a на маршрутах 008b 0.3241312979. Каждый результат оценён после балансировки всех маршрутных сумм и восьми сумм горизонтов. Проверки направления, краёв, нулевого сдвига при равенстве, сумм и перемешанных Test ID прошли. Для отдельного запуска проверок предусмотрен флаг `--test-only`.

В experiments.csv есть результаты каждого метода по датам, горизонтам и квартилям. Пулы посчитаны по объединённым массивам внутри каждой базы. В строках smooth счётчики shift_early и shift_late обозначают маршруты, выбранные причинным правилом для участия в контроле.
