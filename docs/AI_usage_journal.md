# Использование искусственного интеллекта в проекте RWB

## 1. Применяемые инструменты

В ходе разработки решения использовались два ИИ-инструмента:

**ChatGPT** — для анализа условий кейса, изучения данных, исследования ML-подходов, проверки технических решений, объяснения архитектуры моделей и подготовки проектной документации.

**OpenAI Codex** — как ИИ-помощник при программировании, анализе существующего кода и разработке экспериментов по улучшению прогнозирования.

ИИ использовался как вспомогательный инструмент. Итоговые решения оценивались по результатам экспериментов и официальной метрике соревнования.

## 2. Задачи, выполнявшиеся с помощью ИИ

| Направление | Применение ИИ | Полученный результат |
|---|---|---|
| Анализ постановки | Разбор условий RWB и ответов экспертов | Уточнены горизонт прогнозирования, ограничения и единицы измерения |
| Исследование данных | Подготовка методов анализа Parquet и проверки временных рядов | Определены необходимые проверки качества и структуры данных |
| ML-архитектура | Анализ решений Ridge, LightGBM, CatBoost и TCN | Сформированы объяснения принципов работы ансамбля |
| Валидация | Исследование возможной утечки данных и особенностей WAPE + Relative Bias | Сформулированы требования к корректной временной проверке |
| Оптимизация | Анализ архитектуры 008b → 014a → 015a → 019b → 020a | Выявлены направления улучшения суммарного прогноза и распределения нагрузки |
| Программирование | Использование Codex для работы с ML-кодом и экспериментами | Подготовка и модификация программных решений с последующей проверкой |
| Документация | Структурирование технической информации | Паспорт проекта, описание эволюции моделей, задания для Codex |

## 3. Примеры исследованных гипотез

**Гипотеза 1. Исторические значения отгрузок улучшают прогноз.**

В отличие от первоначального baseline, более поздние решения используют лаги целевой переменной и скользящие статистики. Это позволяет учитывать динамику конкретного маршрута.

**Гипотеза 2. Сочетание нескольких алгоритмов позволяет учитывать разные закономерности.**

В ходе развития решения были объединены линейные модели, градиентный бустинг и нейросеть TCN. Разные компоненты анализируют временные зависимости и характеристики маршрутов.

**Гипотеза 3. Прогноз общей нагрузки и её распределение между маршрутами целесообразно рассматривать отдельно.**

Анализ кода показал, что версии 014a–020a используют согласование прогнозов по суммарному объёму сети. Это позволило определить отдельное направление дальнейших экспериментов — улучшение сетевой калибровки.

**Гипотеза 4. Более длинная история помогает учитывать недельную динамику.**

В модели 020a реализован адаптер, анализирующий недельную историю поверх исходной TCN.

Перечисленные пункты описывают исследованные технические подходы. Для доказательства вклада ИИ в конкретные изменения кода необходимо приложить соответствующие запросы, ответы и результаты экспериментов.

## 4. Проверка результатов работы ИИ

Предложения ИИ не рассматривались как доказательство качества модели сами по себе.

Для контроля использовались:

- официальная метрика WAPE + |Relative Bias|;
- временная валидация с учётом доступности исторических данных;
- сравнение версий моделей и сохранённых прогнозов;
- проверка корректности `submission.csv`;
- оценка результата через Public Score конкурсной платформы.

Наиболее успешной из представленных версий является модель 020a. Отображаемый Public Score — 0,325. Точное численное улучшение относительно 019b не установлено из-за округления на платформе.

## 5. Артефакты использования ИИ

Для подтверждения процесса работы предусмотрены:

1. `RWB_model_evolution_explained.md` — технический разбор развития моделей.
2. `CODEX_RWB_improve_020a_prompt.md` — пример подробного задания для ИИ по оптимизации.
3. Python-скрипты моделей 008b–020a — проверяемые программные результаты.
4. Таблицы валидации и экспериментов — объективные результаты проверки гипотез.
5. История взаимодействия с ChatGPT и Codex — подтверждение конкретных задач, выполнявшихся с помощью ИИ.

Скрипты и результаты экспериментов показывают развитие решения, но не доказывают автоматически, что весь код был создан ИИ. Для точного указания авторства необходимо сверить историю разработки.

## 6. Ограничения

ИИ не имеет доступа к скрытым целевым значениям Test и не может достоверно рассчитать конкурсный Public Score без платформы.

Рекомендации ИИ требуют проверки, особенно при построении признаков временных рядов, предотвращении утечек и интерпретации результатов.

Окончательные выводы о качестве моделей должны основываться на выполненных экспериментах, а не на предположениях ИИ.
