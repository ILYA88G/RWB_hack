# Exp_024 — использовать прокси с 25% длинного CatBoost как вторую историческую базу

На 24 000 прогнозах WAPE снизилась с 0,32413130 до 0,32040029. Смесь выиграла на трёх датах из трёх, а абсолютная ошибка верхнего квартиля снизилась на каждой дате. Выполнены все три условия брифа — снижение pooled WAPE, минимум две выигранные даты и рост ошибки Q4 максимум на 0,5% на каждой дате.

B — историческая прокси 021a на маршрутах 008b. C — сохранённый длинный CatBoost, нормированный отдельно на восемь прогнозных сумм B. M — прокси с 25% длинного CatBoost, то есть 0,75 B + 0,25 C. Доля зафиксирована по рецепту 019b до измерения. Все три варианта проверены на одной сетке из 1 000 маршрутов и восьми получасовых горизонтов для каждого origin.

## Граница применимости и воспроизведение

Размер CBM (17 352 748 байт) и SHA-256 `ffb798c1103c7cd7c8fbcfe6f5f39606ad4efbf62dba7fbd0f639ee11fc15795` совпали с записью exp_021/input_manifest.csv. Веса содержат 1 400 деревьев глубины 6, MAE, seed 42 и категориальный route_id. В train_components_019b.py обе выборки по 400 000 строк строятся на префиксе до 30.10.2025 10:30 включительно, последний t равен самое позднее cutoff−8, метка берётся по t+h с проверкой t+h ≤ cutoff. Рецепт сохраняет результат под именем проверенного CBM. Дату поддерживают также проверка минимального origin в predict_model_019b.py, описание проекта и аудит 021. Хеш идентифицирует файл. Отдельного журнала обучающих строк CatBoost среди артефактов refitted нет. На фолде 3 в обучение могла войти цель в 10:30, первая оцениваемая цель — 11:00. На более ранних субботах эти веса неприменимы.

Скрипт один раз читает Train штатной load_history, проверяет сетку, сортирует по timestamp и route_id и сохраняет порядок target_1h, status_1…status_6. load_folds сверяет origins и матрицы меток с OOF. Контроли воспроизвелись — Score 008b 0,3302594869 и WAPE B 0,3241312979. Для B используются сохранённые маршрутные прогнозы и суммы 008b. Чтобы воспроизвести фиксированное правило 021a без обучения, скрипт вычисляет единственный прогноз Ridge с α=180 как взвешенную сумму уже наблюдавшихся остатков на префиксе. Затем применяет штатные proposed_totals и safe_totals по rule.json. Все 24 суммы B дополнительно проверены через архивные значения signed bias каждого горизонта из exp_023, после построения B.

Для C исходные halfhour_causal, BaseCatFeatures и CatFeatures загружаются из исходника 019b без PyTorch. На каждом префиксе с 28.07 выполняется один вызов CatBoost на 8 000 строках. Проверены порядок всех 142 признаков, route_id и горизонт. Декодирование — max(выход, 0) × scale + offset. Проверки прошли для конечности, неотрицательности, равенства восьми сумм B/C/M при rtol=10⁻¹² и равенства общего signed bias на каждой дате.

Полный запуск из корня репозитория и отдельная проверка архива:

```powershell
.\exp_024\.venv\Scripts\python.exe -B exp_024/long_cat.py
.\exp_024\.venv\Scripts\python.exe -B exp_024/long_cat.py --verify-only
```

Windows x64, CPython 3.13.1, CatBoost 1.2.10 (1 поток), NumPy 2.5.4, pandas 3.1.1, PyArrow 26.0.1. Отдельный venv exp_024 использует также пакеты exp_021 через файл exp021.pth. Для создания свежего окружения достаточно установить версии из exp_021/requirements.txt и catboost==1.2.10 под CPython 3.13.1. Время полного расчёта от загрузки весов до записи CSV и проверки архива — 20,13 с, без установки и старта интерпретатора.

Архив long_cat_folds.npz содержит cat_raw (float64, 3 × 1 000 × 8) после декодирования, B_totals (3 × 8) и оси fold, origin, route_id, horizon. Отдельная проверка восстановила B из маршрутных OOF и B_totals, нормировала cat_raw и получила pooled WAPE смеси 0,320400285794. Конкурсная рекомендация — оставить 021a. Три ранее изученные даты дают рабочее основание проверять следующие идеи на двух базах. Они не устанавливают статистическую значимость, качество полной 020a/021a или оптимальную долю уже присутствующего в 021a CatBoost.
